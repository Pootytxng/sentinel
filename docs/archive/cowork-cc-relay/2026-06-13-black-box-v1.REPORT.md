## Judgment calls (flagged for your audit)
1. **IPC return type = `BlackBoxReport { incidents, skipped_sources }`, not a bare `Vec<Incident>`** (the work order / spec §Architecture said `Vec<Incident>`). Reason: the **elevation-honesty hard line** ("SAY a source was skipped, never silently drop") cannot be satisfied by a bare `Vec` — if `\Minidump`/a channel is unreadable and the readable sources found nothing, a `Vec` has nowhere to report the gap. The thin wrapper is the minimum needed to keep that hard line. Pure `Vec<Incident>` lives inside it.
2. **Collector scope = Event Log (all 7 families) + `\Minidump` skip-honesty; WER + `Win32_ReliabilityRecords` + minidump-header bugcheck parse DEFERRED to v2.** Reason: **Event Log `Application Error 1000` already carries the same faulting app/module/exception** that WER's `Report.wer` does — via structured `EventData` (language-independent, non-elevated) — so adding WER in v1 would **double-report every app crash** without a dedup layer that's beyond v1's tight scope; Reliability is spec-marked "optional in v1"; and the BSOD bugcheck code comes from the (non-elevated) `BugCheck 1001` event, so the admin-gated minidump header is redundant for v1. Net: the spec's honest read-only timeline + last-vitals overlay is fully delivered from Event Log; the deferred sources are enrichment, recorded so scope doesn't creep. **If you want WER in v1, it needs a (crash-time, app) dedup pass against the Event Log — say the word.**
3. **Over-fetch-by-ID then provider-guard** (rather than a per-(provider,id) `Get-WinEvent` filter): simpler one-shot query, and the pure `classify_incident` guard is the language-independent filter. Live-proven correct on this rig (see QA).
