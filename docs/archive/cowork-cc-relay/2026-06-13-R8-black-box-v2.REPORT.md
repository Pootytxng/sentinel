## Lane 1 — Black Box v2 — ✅ (`4e87a3e`)

**What changed.** A triage layer over the v1 evidence reader. It **never asserts a cause** — it says "the
evidence is **consistent with** X (here's what we saw) → the **reversible** step to confirm is Y," and
**refuses to guess** when no rule clears its bar. Pure, no new OS call, no mutation, zero outbound.

- **Types:** `Assessment { consistent_with, strength, evidence, next_step, beyond_us }` ·
  `Strength { Strong | Partial | Weak }` (serde `lowercase`) · `NextStep { headline, detail, reversible
  (always true), research_only }`. Added an optional `assessment` to `Incident` (`skip_serializing_if
  none` → a flag-OFF incident serializes byte-identical to v1) + an internal `#[serde(skip)] kind` for the
  pure pass.
- **`assess(incident, recent_context)`** — 4 starter rules in priority order, first-to-clear wins:
  1. **overheating-consistent** — measured GPU ≥85 °C before a GPU-timeout/unexpected-shutdown → *Strong*;
     a WHEA machine-check → *Strong* if repeated (or temp-corroborated), else *Partial*. Honest about
     WHEA's breadth (heat / power / memory). Next: check temps under load (reversible).
  2. **graphics-driver-consistent** — the same GPU module timing out across ≥2 crashes, temps **not** high
     → *Strong*. Next: clean-reinstall the driver (reversible; roll back via Device Manager).
  3. **app-specific (not your PC)** — a lone app crash/hang with **no** system event within ±10 min →
     *Strong* app-side. Next: verify game files / update (reversible).
  4. **power / hard-lock-consistent** — Kernel-Power 41 / 6008, no dump, no high temps → *Partial*
     (inherently ambiguous, and says so). Next: reseat cables / try another outlet (reversible); a failing
     PSU is **research-only**, never "do this."
  - **beyond-us escape hatch** — a BSOD that didn't resolve to overheating → *Weak*, `beyond_us: true`,
    "look up the bugcheck code + take the receipt to a human." Never a forced rule. No rule clears →
    `None` (evidence-only v1 + "not enough recorded").
- **Gate:** `blackbox_v2_gate()` is **HARD-FALSE in release** — both its `#[cfg(test)]` and
  `#[cfg(all(debug_assertions, not(test)))]` blocks compile OUT of a shipped binary, so it reduces to
  `false` and the env opt-in is never even read there. A DEBUG-only `COMPY_BLACKBOX_V2_PREVIEW=1` drives
  the owner's `npm run tauri dev` preview; a `#[cfg(test)]` thread-local force-seam exercises the gated
  path in tests without touching the shipped gate.
- **Frontend:** under each assessed incident, a quiet **"What this points to"** line (consistent-with + a
  strength **WORD** chip — "Strong/Partial/Weak signal", never a %) → the **evidence rows** → ONE next
  step (research-only steps clearly tagged "Worth researching") → a local-only **"Did this point you the
  right way?" yes/no** (the honesty feedback loop; capped local log, no network). Renders only when the
  gate populated `assessment`; flag-OFF = exact v1.

**Council.** 🟢 Contrarian: the lethal move is a confident wrong verdict — v2 **structurally cannot**: no
percentages (test-enforced), "consistent with" only, refuse-to-guess returns `None`, and the whole layer
ships **OFF**. First-Principles: triage = name what the evidence supports + the reversible confirming
action, not divine the cause. Expansionist: the local "did this help?" signal is the seed of v2.1's
"no <incident> since" payoff and a field-proven rule set before any v3 affiliate. Outsider: "Worth
researching" framing + the beyond-us hatch keep it out of the scam-repair lane it would otherwise
resemble. Executor: smallest shippable = 4 rules behind a flag, no new OS call, no mutation, no installer.
