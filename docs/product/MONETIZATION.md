# Monetization

**Derived from:** `../PRODUCT_CONSTITUTION.md`

Compy monetization follows demonstrated durable value. No historical price, tier, subscription plan, affiliate scheme, or processor choice is canonical merely because it appeared in an older doctrine.

## 1. Non-negotiables

- Core safety and rollback cannot become hostage features.
- No monetization path may require scareware, fake urgency, misleading severity, or dark patterns.
- Privacy/network behavior remains governed by Architecture Locks and explicit consent.
- Technical recommendations must not be biased by affiliate economics.
- Pricing remains a hypothesis until real users experience value and respond to real offers.

## 2. Current default hypothesis

For consumer Compy, the strongest current hypothesis is:

- genuinely useful free core;
- paid depth/convenience/advanced experimentation rather than paid safety;
- one-time/lifetime or perpetual + maintenance as primary structures to test before a forced monthly subscription;
- annual/subscription only if recurring intelligence/service value is clearly demonstrated.

This is a hypothesis, not a constitutional price decree.

## 3. Candidate Free value

Free should be good enough to build trust and demonstrate the product thesis. Candidate areas:

- core machine understanding;
- basic Health/Care;
- essential incident evidence;
- core safe optimization journey;
- rollback of Compy-applied changes;
- basic benchmarking/receipts;
- core Blackbook/methodology access.

Exact boundaries require user evidence and must never make safety unusable.

## 4. Candidate Pro value

Potential paid value includes:

- deeper historical comparison/correlation;
- advanced experiment orchestration;
- richer multi-objective profiles;
- advanced reports/export;
- multi-rig profiles;
- advanced/experimental tuning workflows;
- richer case intelligence;
- professional/repair-shop workflows;
- long-term evidence/history convenience.

A feature belongs in Pro because users value its depth or ongoing utility, not because the free product needs artificial pain.

## 5. Pricing tests

Do not choose price solely from competitors.

After activation, test real offers with realistic price points and observe behavior.

A sensible initial one-time/lifetime research band may include offers around the existing utility market range, but the final number must come from Compy-specific willingness-to-pay evidence.

## 6. Consumer subscriptions

A recurring subscription requires recurring value that a user can perceive without marketing fiction.

Possible justification could eventually include continuously updated intelligence, advanced historical analysis, multi-rig services, or professional workflows.

“Because SaaS revenue is better” is not sufficient product justification.

## 7. B2B / repair shops

Do not build a separate shop product until interviews establish workflow value.

If technicians report material time savings from case intake, repeatable diagnostics, evidence, rollback, and customer-safe reports, seat-based recurring pricing may be more natural than consumer subscription pricing.

## 8. Affiliate hardware

Affiliate revenue is permitted only behind a strict independence contract:

- limiter/evidence determination happens before retailer economics;
- no-upgrade is a valid result;
- cheaper non-purchase remedies appear first when appropriate;
- compatibility and system balance are considered;
- disclosure appears next to the commercial link;
- payout size never influences technical ranking.

## 9. Activation order

Before arming broad monetization:

1. prove useful external product journeys;
2. establish trusted public distribution/signing;
3. identify which value users want more of;
4. test willingness to pay;
5. select price/model;
6. only then wire the minimum payment/issuance operation needed.

The existing dark license infrastructure may be reused if it still fits this model, but it does not dictate the model.
