# Spec — Black Box v2 (Paramedic Mode: triage + safe next step)

> **Status:** READY FOR CC, behind a default-OFF flag. Council-approved 2026-06-13 (full three-stage;
> owner said "consult the council and be persistent — GO"). v2 is the honesty-critical layer, so the
> council IS the sign-off proxy and the guardrails below are LAW. Built app-only behind a flag; **does
> NOT reach testers** until an owner-gated installer rebuild + the owner's review of the causal copy.

## The law that makes v2 safe (read first)
**v2 is a TRIAGE + SAFE-NEXT-STEP engine, NOT a verdict engine.** It never says "the cause is X." It says
"the evidence is **consistent with** X — here's what we saw — and the safe, reversible next step to
**confirm** it is Y." This is the entire reason v2 doesn't break the never-claim-unmeasured law: it names
what the evidence supports + the reversible confirming action, and it **refuses to guess** when the
evidence is thin. "We can't tell from what Windows recorded" is a first-class, intended output.

Hard rules (all enforced by tests):
- **Strength in WORDS, never percentages** — `Strong` / `Partial` / `Weak` evidence. No "73%".
- **Never assert a cause.** Copy is always "consistent with…" / "points toward…" + the evidence list.
- **Every next step is REVERSIBLE and SAFE.** Driver clean-reinstall, verify game files, check temps
  under load, test a drive — yes. **Never** instruct an irreversible/risky action (BIOS/UEFI, RMA,
  repaste, voltage); those may only appear as "here's what to *research*," clearly framed, never "do
  this." Compy performs NONE of these — v2 is advisory text only (no new mutation).
- **Refuse-to-guess threshold.** If no rule clears its evidence bar, output evidence-only (v1 behavior) +
  "not enough recorded to point anywhere safely." Better silent than wrong.
- **Beyond-us escape hatch.** Ambiguous BSOD bugchecks / rare WHEA → "this is beyond what Compy can
  safely advise — here's the raw evidence to take to a human/forum." Never force a rule.

## Output shape (layers on v1's `Incident`)
Add an optional `assessment: Option<Assessment>` to `Incident` (v1 `IncidentKind` + evidence + `LastVitals`
unchanged). `Assessment { consistent_with: String, strength: Strength, evidence: Vec<String>, next_step:
NextStep, beyond_us: bool }`; `Strength { Strong, Partial, Weak }`; `NextStep { headline, detail,
reversible: true /* always */, research_only: bool }`. Pure function `assess(incident, recent_context) ->
Option<Assessment>` over already-collected v1 data — no new OS calls needed for the starter rules.

## Starter rules (3–4 strong ones; everything else stays evidence-only)
1. **Overheating-consistent** — `HardwareError` (WHEA thermal) repeated, OR `GpuTimeout`/`UnexpectedShutdown`
   with `LastVitals` peak GPU temp ≥ ~85 °C in the pre-incident window. → *Strong* (with WHEA) / *Partial*
   (temp-only). Next step: "check temps under load" (reversible, how-to).
2. **Graphics-driver-consistent** — recurring `GpuTimeout` (Display 4101) on the same faulting module
   (amdkmdag/nvlddmkm) across ≥2 incidents, temps NOT high. → *Strong*. Next step: clean-reinstall the GPU
   driver (reversible; link the existing walkthrough if present).
3. **Power/hard-lock-consistent** — `UnexpectedShutdown` (Kernel-Power 41 / 6008) with NO dump and NO high
   temps. → *Partial* (this one is inherently ambiguous — keep it honest). Next step: the safe checks
   (seat power cables, test on another outlet, note if it's under load); PSU replacement is *research-only*.
4. **App-specific (not your PC)** — a single `AppCrash`/`AppHang` in one game with no system-level events
   around it. → *Strong* that it's app-side. Next step: verify game files / update the game (reversible).

Each rule emits the `consistent_with` phrasing + the **exact evidence rows it fired on** (the user sees
*why*) + ONE reversible next step. A rule that can't meet its bar does not fire.

## Frontend (in the existing Lab Black Box card)
Under each incident that has an `assessment`: a quiet "What this points to" line (consistent-with +
strength chip) → the evidence it's based on → the safe next step. Evidence-only incidents render exactly
as v1. Include the **"Did this help?" (yes/no)** control on a next-step (stored locally for now; it's the
honesty feedback loop — wrong rules surface). NO percentages anywhere.

## HARD LINES
- **Behind a default-OFF flag** (gaming_mode-gate pattern) — `blackbox_v2_gate()` false until owner flips
  it; v1 is the shipped behavior until then.
- **Read-only / advisory text only.** No new mutation, `actions.rs` untouched, no new OS calls for the
  starter rules, zero outbound, no kernel driver, anti-cheat-safe.
- **No affiliate / no "buy this" in v2** (council blind-spot: don't monetize an unproven diagnosis). Parked
  to v3 behind the telemetry gate, only after rules are field-proven.
- **Never fabricate, never assert a cause, strength-in-words, refuse-to-guess** — per the law above,
  test-enforced.
- **App-only; NO installer cut.** Reaches testers only on an owner-gated rebuild AFTER the owner reads the
  causal copy.

## Verify
- `blackbox.rs` (or `blackbox_v2.rs`) pure-core tests: each rule fires ONLY on its evidence bar; thin
  evidence → `None` (refuse-to-guess); no `Assessment` ever contains a percentage or an irreversible
  next_step (assert `reversible==true`); beyond-us path on ambiguous bugcheck; flag OFF → no assessments
  emitted at all.
- cargo + clippy clean · npm + tsc + vite clean · `/check` + `/security` clean (no new mutation/outbound;
  flag gate verified OFF by default).
- `npm run tauri dev` so the owner can preview WITH the flag on (dev only).

## Phasing
- **v2.0 (this spec):** triage + safe next step, 3–4 rules, flag-OFF.
- **v2.1:** the measured payoff — after a suggested fix, show "no <incident type> since" (closes the
  doctrine loop) + aggregate the local "did this help?" signal.
- **v3 (gated):** fleet "crash brain" + honest affiliate on confirmed hardware causes — NEW outbound
  boundary, `/security` review + owner sign-off, only after rules are field-proven right.
