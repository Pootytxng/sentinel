## Origin (owner ask, 2026-06-13)

Owner wants Paramedic Mode to gain crash/freeze diagnosis — "pinpoint why a game crashed or froze,
how to fix it, how to prevent it." He explicitly does **not** want a whole new tab; it folds under
the Paramedic Mode umbrella with its own wording. He delegated the naming to Cowork.

The council (full three-stage, 2026-06-13) reframed the ask: **"foolproof / exact" crash diagnosis
collides head-on with the #1 product law (never claim unmeasured).** Crash root-cause is
probabilistic; many freezes leave no artifact at all. The honest — and uniquely defensible — product
is **translation + correlation, not divination**: collect the crash evidence Windows already records,
lay it against Compy's own pre-crash telemetry (which no competitor has), and present it in plain
English, **never guessing past the evidence.** That honest version IS the moat in a category that is
100% snake oil.

## v1 scope — what it DOES (read-only, honest, no causal claims)

On demand (button: **"Scan for recent crashes"** — read-only, no background watcher in v1), Black Box
collects the last N (cap 25) crash/freeze/instability *incidents* Windows recorded, renders each in
plain English with a timestamp, and — when a Compy session overlapped that moment — shows the
**last vitals** strip. Raw evidence (event IDs, faulting module, bugcheck code) lives behind a
**"show the receipt"** expander. v1 makes **NO causal claim and NO fix prescription** beyond what an
event literally states (a TDR event *says* "display driver stopped responding" — reporting that is not
diagnosing it). Probable-cause + fix/prevention = v2, gated (below).

### Data sources — ALL user-mode (no kernel driver), anti-cheat-irrelevant (reads OS logs/files, never
touches a game process, never injects)

1. **Windows Event Log** via `Get-WinEvent` (PowerShell, read-only) or the `windows` crate EvtQuery:
   - **System** channel: **Kernel-Power Event ID 41** (the unexpected-shutdown / hard-lock / power-loss
     signature — this is how we catch freezes that leave NO crash report) · **BugCheck 1001** (BSOD +
     bugcheck code) · **Microsoft-Windows-WHEA-Logger 17/18/19** (machine-check hardware errors —
     thermal/power/RAM/PCIe signals) · **Display 4101** ("nvlddmkm/amdkmdag stopped responding and
     recovered" = the classic GPU timeout/TDR).
   - **Application** channel: **Application Error 1000** (faulting app + faulting module + exception
     code) · **Application Hang 1002** (the app stopped responding).
2. **WER (Windows Error Reporting)** — `%ProgramData%\Microsoft\Windows\WER\ReportArchive` /
   `ReportQueue` `Report.wer` files (faulting module, exception code, app name). Read-only file reads.
3. **Reliability** — `Win32_ReliabilityRecords` (WMI) for the user-friendly critical-event timeline.
   Optional in v1 if Event Log already covers it; nice for plain-English phrasing.
4. **Minidump presence** — `%SystemRoot%\Minidump\*.dmp`: v1 only DETECTS presence + timestamp + reads
   the bugcheck code from the header. **No symbolization in v1** (full dump analysis = v2).
5. **Compy's own pre-crash telemetry** — `sessions.rs` `SessionSummary` (`started_at` RFC3339 + duration,
   `peak_gpu_temp_c`, `peak_gpu_usage_pct`, `stutter_timeline: Vec<(u32,f64)>`, `stutter_events`). Match a
   crash timestamp to a session window → surface the "last vitals" (e.g. "frametime spiking, GPU 84°C in
   the 30s before"). **This is the unique correlation no other tool has.**

### v1 output (per incident)
- Plain-English headline (Sarah & Caleb bar — jargon translated, never defined with jargon). E.g.
  *"Your graphics driver stopped responding and recovered — Jun 12, 9:42 PM, while Helldivers2 was
  running."*
- A neutral evidence tag: `GPU timeout` · `App crash` · `App hang` · `Unexpected shutdown / hard
  freeze` · `Blue screen` · `Hardware-logged error`.
- **last vitals** strip IF a session overlapped (else: *"Compy wasn't monitoring at that moment — no
  vitals to show"* — honest about the gap, never invented).
- **show the receipt** expander: raw event ID(s), faulting module, exception/bugcheck code, source
  channel, and whether a channel was skipped for lack of elevation.
- When Windows recorded NOTHING for a suspected freeze: say exactly that. **Never fabricate a cause.**

## Architecture (follows existing codebase patterns)

- **New module `src-tauri/src/blackbox.rs`** — mirror `sessions.rs`/`priorities.rs` shape: a **pure core**
  (`parse_*` / `classify_incident` / `correlate_vitals` over already-fetched strings + serialized
  session data) with unit tests, plus a **thin Windows collector** (the PowerShell/`windows`-crate calls)
  isolated at the edge. Pure functions carry the logic + tests; the OS calls stay dumb.
- **New IPC `get_crash_blackbox`** registered in `lib.rs` `generate_handler!` (same pattern as
  `get_diagnostics` / `get_session_summaries`). Returns `Vec<Incident>` (typed, serde).
- **Frontend:** a `BlackBox` component rendered as a `LabSection` in `Lab.tsx` (collapsible card,
  matches Diagnostics). On expand → "Scan for recent crashes" button → `invoke("get_crash_blackbox")`
  → render the incident list. No auto-run on mount in v1 (explicit user action; keeps Lab cheap).

## HARD LINES (must NOT cross — locked-gate + doctrine compliance)
- **Read-only.** No mutation, no new mutation primitive, `actions.rs` untouched. (No rollback contract
  needed — it changes nothing.)
- **No kernel driver, no injection** — every source above is user-mode OS logs/files. Anti-cheat-safe.
- **Zero outbound network.** v1 is 100% local. (Fleet aggregate = v3, behind the telemetry gate.)
- **No fabricated / unmeasured claims.** v1 reports recorded evidence only. No "probable cause," no
  confidence %, no fix list in v1 — those are v2 and must be evidence-gated.
- **Honest about gaps + elevation.** If the System/Security channel or `\Minidump` needs admin and we're
  non-elevated, read what's available and SAY a source was skipped — never silently drop or fake it.
- **Plain language.** Event jargon translated for non-technical readers; raw IDs behind the receipt
  expander only.
- **No new always-on background process in v1.** On-demand scan only (the always-on watcher is a v2/Pro
  consideration with perf + "booster-app optics" caveats — see council Outsider/Contrarian).

## Phasing (v2/v3 are NOT in this build — recorded so scope can't creep)
- **v1 (this spec):** read-only evidence timeline + last-vitals overlay. Zero causal claims. Ships now.
- **v2 (gated):** probable-cause + confidence level + plain-English fix/prevention, built ONLY from
  evidenced rules (e.g. repeated WHEA-thermal + high last-vitals temp → "overheating is the likely
  driver, X% confidence, here's the evidence"). Fix suggestions must respect rollback-first — anything
  irreversible (BIOS, RMA, repaste) is *advice with eyes open*, never an action Compy takes. Liability
  framing required (council "duty-of-care" miss).
- **v3 (telemetry security gate — doctrine stop-rule 3):** opt-in anonymized crash signatures →
  fleet-aggregate "known crash" intelligence ("rig like yours + this driver + this game = known
  timeout"). NEW outbound boundary → own spec + `/security` review + owner sign-off before any ship.

## Council strip (5-lens, full audit at handoff — Cowork, 2026-06-13)
- 🔴 **Contrarian:** the lethal move is shipping the word "foolproof/exact." v1 structurally cannot —
  it makes zero causal claims. Watch that v2 never regresses this; honesty is the brand's life.
- **First-Principles:** product = translate evidence Windows already wrote + correlate Compy's unique
  pre-crash vitals. Not divination. Dissolves the doctrine conflict.
- **Expansionist:** v1's incident corpus is the seed of the v3 fleet "crash brain" (Pro + affiliate +
  B2B). Build the recorder honestly now; the flywheel compounds later.
- **Outsider:** "Black Box" + "show the receipt" signal *evidence, not magic* — keeps it out of the
  scam-repair lane it would otherwise resemble.
- **Executor:** smallest shippable = the on-demand read-only timeline in a Lab card. No new tab, no
  mutation, no driver, no network. Ships this build.
